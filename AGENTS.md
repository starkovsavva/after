# Repository Guidelines

## Project Structure & Module Organization

After macOS client and cross-platform Tauri preview. Preserve historical bundle IDs, data paths, Keychain identifiers, `POSLE_*` and Rust/FFI names.

- `desktop/src/`: React/TypeScript UI, translations, styles, tests; `desktop/e2e/`: Playwright scenarios.
- `desktop/src-tauri/`: Rust host, typed IPC, Windows capture/media adapters, and `tests/real_engine.rs`.
- `rust-core/src/`: storage, search, tasks, cards, jobs, CLI, platform adapters. Keep domain rules here.
- `process-runtime/`: scoped child processes shared by engine/host; Unix groups and Windows Job Objects stay in adapters.
- `Sources/AfterApp/`: SwiftUI/AppKit; `AfterCore/`: portable models; `AfterPlatform/`: contracts; `AfterLocalization/`: translations; `AfterPlatformMacOS/`: Apple adapters. `Tests/` contains portable and native checks.
- `backend/`: Python speech runtime. `scripts/`: verification/build tooling. `packaging/` and desktop icons contain assets.
- `backend.md` describes canonical storage; `docs/architecture/platform-boundaries.md` and `docs/design-system.md` describe native boundaries and UI. `docs/desktop.md`: desktop setup and limitations; `docs/development.md`: macOS workflow. `docs/specs/` contains plans; verify descriptions against code.

## Build, Test, and Development Commands

Desktop needs Node 24+, Rust stable, and Tauri dependencies; Arch setup: `docs/linux.md`. From root:

```sh
cargo build --manifest-path rust-core/Cargo.toml --locked --target-dir .build/rust
python3 scripts/stage-desktop-engine.py
cd desktop
npm ci --ignore-scripts
npm run tauri dev
```

After core/backend changes, rebuild/stage the engine and speech source with `scripts/stage-desktop-engine.py`, then rebuild the host to refresh pinned digests. Never commit generated resources or binaries.

In `desktop/`: `npm run build` checks TypeScript/builds Vite; `npm test` runs model tests; `npm run test:e2e` runs Playwright (install Chromium). `npm run dev` serves UI; `/?demo=1` enables synthetic data.

Run `cargo test --manifest-path desktop/src-tauri/Cargo.toml --locked` for host tests; substitute `rust-core/Cargo.toml` for core tests. Real-engine/installer checks: `docs/desktop.md`, `.github/workflows/windows-preview.yml`.

`python3 scripts/verify.py desktop` checks process-runtime/core/frontend/host/real IPC without Swift and stages the just-built engine plus backend before host compilation; do not rely on existing local staged artifacts. Run process tests alone with `cargo test --manifest-path process-runtime/Cargo.toml --locked --target-dir .build/rust`. Pure models/validation: `rust-core/src/domain/`; boundaries: `python3 scripts/check_layers.py`; native adapters/resource lookup: host `platform.rs`.

For macOS, `python3 scripts/verify.py quick` builds/tests Swift, Python, and Rust; `native` requires a graphical Mac session; `queue` runs only synthetic Swift/Rust queue checks. `bash scripts/build.sh` requires an Apple signing certificate.

## Coding Style & Naming Conventions

Match nearby code: two-space TypeScript, four-space Swift/Rust/Python; PascalCase types/components, camelCase UI members, snake_case Rust/Python functions. No shared formatter exists. Preserve typed IPC, revisions, filesystem protections.

## Testing Guidelines

Use Node, Playwright `*.spec.ts`, Rust, Python `test_*.py`, and Swift checks. Use disposable libraries and debug `AFTER_DATA_DIR`; no coverage threshold exists. Mac checks need Apple tools; canonicalize temporary fixture roots before strict filesystem checks (`/var` is a system alias to `/private/var`), and keep aliases inside protected roots rejected; Linux needs WebKitGTK 4.1 (not 6.0). Desktop uses `app.posle.desktop`. Browser shortcut checks must use `Meta` on macOS and `Control` on Linux/Windows, matching `desktop/src/shortcuts.ts`.

## Commit & Pull Request Guidelines

Commit every completed, verified milestone separately before starting the next one. Include implementation, relevant checks, and current documentation; never bundle unfinished later stages. Do not push unless requested. Use imperative subjects. PRs describe behavior, issues, checks, platform limitations; include UI screenshots.

## Architecture & Portability

Target full Arch support while preserving macOS/Windows; Linux microphone uses local libpulse; explicit CLI CPU ASR works with managed Parakeet. System audio, diarization setup and speech setup UI remain pending; configured local transcription now has meeting controls. Follow SOLID: UI → application → domain; OS details stay in adapters. Workspace: `application/workspace.rs`, contracts in `application/ports.rs`. Queue: `application/jobs.rs`, transaction/clock/ID ports in `application/job_ports.rs`, models/transitions in `domain/jobs.rs`. Live rules: `domain/job_runtime.rs`; Swift `NativeJobRuntime` owns transient state and interprets decisions; never persist/reuse this state. SQL/files/time/identity adapters live in `infrastructure/`. Unix CPython inventory verification lives in `infrastructure/runtime_tree.rs`; macOS `python_runtime.rs` owns compiled policy/layout, venv and loader binding. The shared verifier must never select artifacts or load Python; Linux x86_64 GNU pins CPython in `backend/python-runtime-linux-x86_64.json`; `platform/linux/python_runtime.rs` verifies it through the same native CLI mode. Generation installer: `application/runtime_install.rs` orders steps through a port; shared `infrastructure/generation_store.rs` owns Unix leases, candidate identity/cleanup and atomic publication for runtimes/models; never cross-publish candidates between scopes. Linux `runtime_install.rs` stages/verifies CPython and venv, then atomically publishes `runtime/linux-python/active.json` under `.install.lock`. Never delete the lock or previous/unknown generations. Active selection: `runtime_active.rs` validates bounded `active.json`, UUID/target/version/path, pinned CPython and shared `infrastructure/runtime_venv.rs` binding. Retain its guard through execution; pointer updates do not invalidate an already selected generation. Mac uses the same venv binding. Installer does not publish speech readiness; Speech launch uses `application/speech_launch.rs` and platform adapters; shared `worker.rs` retains the runtime guard through child exit and rechecks before spawn. Linux runs the selected CPython with `-B -u -E -s`; macOS keeps its branded helper. Apple bundle parsing lives in `platform/apple_bundle.rs` (compatibility export preserved). Linux CPU dependencies use pinned `backend/python-wheels-linux-x86_64.json` and optional `--profile linux-cpu` (`--wheelhouse` for offline input). Artifact copy verifies size/hash before pip; source builds/index resolution are disabled. CPU inference/packaged FFmpeg are probed before activation; this is not installed-package attestation or model readiness. Managed model: `asr_model.rs` facade, application install port and `infrastructure/asr_model_store.rs`, pinned `backend/asr-model-parakeet-v3-int8.json`. Explicit CLI `--posle-install-asr-model --root <root> (--archive <file> | --download)`. Set `asrModelPath` explicitly; shared worker captures one `application/speech_launch.rs` SpeechSettings through `infrastructure/speech_settings.rs` for credential admission, model guards and backend execution; keep guards through cleanup. Snapshot presence is strict (empty/invalid never falls back); limit 256 KiB UTF-8. Python `job_settings.py` shares this contract. Explicit model paths must be absolute with home aliases expanded before selection. Python media accepts host-selected venv (`sys.prefix`), not a fixed directory; normalize system ancestor aliases (macOS `/var` → `/private/var`) while rejecting aliases inside runtime. Unix shell fixtures use PATH-resolved `sleep`, not Linux-specific `/usr/bin/sleep`. Explicit offline preflight: `posle-engine check-speech --root /owned/root --backend /trusted/backend` uses the same guarded runtime/model launch, minimal local snapshot and no credentials. It decodes synthetic silence and checks private FFmpeg, requires exactly one bounded completion, and writes no meeting result. It is not automatic startup readiness or a diarization/accuracy claim. Backend logic lives in `speech_check.py`, included in the build-pinned source inventory. CLI ASR is verified on synthetic English speech; other-language quality is unverified. See `docs/decisions/managed-parakeet-model.md` and opt-in `scripts/check-linux-asr.py`; default selection/UI/diarization remain pending. Native local speech publication: `application/speech_execution.rs` ports, `domain/speech.rs` output validation, `infrastructure/speech_publication.rs` copied inputs/revision CAS/journal, `speech_job.rs` composition. Explicit native `--posle-speech-job` uses stdin request/inspect; local and diarization=false only. Atomic transcript `_posleSpeechReceipt` and attempt token stay out of renderer DTOs. Probe receipts before rerun; preserve unknown journal/backup/stages. Native durable speech queue: `desktop_speech_queue.rs`/`desktop_speech_service.rs`, scoped `desktop-speech`, explicit Run and receipt-only startup recovery. `infrastructure/job_database.rs` owns the protected jobs.sqlite connection/migrations shared by queue/query adapters. Shared attempt controls/recovery live in `application/attempt_execution.rs`/`job_recovery.rs`; scoped SQL adapter in `infrastructure/attempt_store.rs`, shared native framing in `native_queue_transport.rs`. Import compatibility exports remain. Never recover a live scope or infer on startup. `speech_process.rs` shares bounded process exchange independently of the typed completion schema; the publication adapter still validates its exact receipt. It retains an inherited speech lease across publisher lifetime; typed leases distinguish import/speech. Queued SDKs use explicit Unix `spawn_contained` inside the publisher's owned group. Validated binary `NativePublisherScope` flushes acknowledgement then intentionally ends that group (SIGKILL can follow success); probe durable receipts rather than trusting exit status. Never apply this to a caller/terminal group. Queue read models exclude config/receipt/tokens. Tauri backend source is staged from `backend/desktop-speech-files.json` into `binaries/speech-backend`; build.rs checks it against checkout source and pins hashes. Native `LibraryBridge.speech_backend()` returns a recheckable source grant; it is not runtime/model readiness. Native speech host binding: `speech_queue.rs` port and `speech_queue_connection.rs` adapter use the shared transport; `LibraryBridge.open_speech_queue()` retains/rechecks backend source through owner exit. `queue_models.rs` owns grant-free state/cursors with import compatibility reexports. Platform selection stays in `platform.rs`; Windows refuses unsupported speech before spawn. Native `EnqueueCheck`/`RunCheck`/`GetCheck`/`CancelCheck` use independent `desktop-speech-check` rows under the same speech lease. `desktop_speech_checks.rs` composes resource admission and joins, `application/speech_check.rs` owns attempt policy, and shared progress belongs to `speech_progress.rs`. Check work contains only minimal local settings; completion binds operation/token/settings revision. SDKs run in an inherited native publisher scope with a ten-minute deadline. Startup marks unfinished checks interrupted without inference; successful rows are historical results, not permanent readiness grants. Check summaries expose no settings/paths and stay outside transcription history. Renderer check commands (`speech_check_status`, `start_speech_check`, `cancel_speech_check`) are ACL-limited to the local main window. `speech_checks.rs` owns current-check policy; `speech_session.rs` owns one lazy, shareable native session. Passive empty status never opens a queue; failed mutations are never replayed. Settings exposes `SpeechCheckPanel` only for the host speechChecks capability, which means source/platform support, not runtime readiness. UI epochs reject delayed status after user actions, and closing/reopening settings reconnects to the host-owned check. Native `Start`/`Meeting`/`Resume` now support meeting-based submission/status and attempt-fenced continuation. `application/speech_submission.rs` owns submission policy through a port; `infrastructure/speech_submission.rs` uses an indexed, scope-filtered pending lookup before LIMIT, independent of history pages. Existing pending work is returned without implicit execution or settings changes; Resume reconciles receipts first. Shared private work/receipt models live in `application/speech_work.rs` with compatibility exports from execution. Tauri `speech_transcriptions.rs` exposes ACL-limited status/start/resume/cancel with meeting-bound summaries and expectedAttempt; checks/transcriptions receive the same lazy session from the composition root. `TranscriptionPanel` uses the speechTranscription capability plus media availability, confirms replacement of existing transcript/summary, rejects stale reads via epochs and refreshes the library on publication. Opening a meeting only reads status; queued/interrupted work needs explicit continuation. Unknown action results disable mutations until a status read succeeds. Meeting IDs follow the existing storage contract (1–128 ASCII letters/digits/`-`/`_`), shared in `domain/meeting_ids.rs`; operation/attempt tokens remain canonical UUIDs. Native `Prepare` takes only a meeting ID: `application/speech_preparation.rs` uses a settings/revision/identity port; `domain/speech_settings.rs` projects only explicit local selection, excluding unrelated settings/credentials; the infrastructure adapter reads settings, rejects relative/traversing model paths and inspects canonical revision. Preparation does not enqueue or claim runtime readiness; enqueue retains source CAS. Runtime/model setup UI remains pending; historical checks do not grant permanent readiness. See `docs/decisions/durable-speech-queue.md` and `native-speech-publication.md`; `install-runtime` refuses unsupported speech setup instead of invoking the Mac shell. Explicit native CLI: `--posle-install-python-runtime --root <owned absolute root> (--archive <file> | --download) [--profile linux-cpu]`. CPU fixture: `python3 scripts/check-linux-speech-profile.py --download`. Opt-in real CPython/venv fixture: `python3 scripts/check-linux-python-runtime.py --download`; no execution before archive and tree verification. Keep claim/admission/dependencies and chain writes transactional. Knowledge SQL/rebuild lives in `infrastructure/workspace_repository/`; mixed-inventory checkpoint filesystem policy is isolated in `knowledge_mixed_inventory/checkpoint_files.rs` (Unix modes, Windows protected/pinned adapters); optional vectors/source cleanup use composition boundaries, preserving private data when adapters are unavailable. Import WorkerHost: host `worker_host.rs` port, `process_worker.rs` adapter, engine `desktop_worker.rs`; bounded progress/cancel protocol and exact commit receipts. Native `imports.rs` owns transient UI status. Host `import_queue.rs` defines a native-only durable queue port; `LibraryBridge.open_import_queue()` returns its leased `queue_connection.rs` adapter. Shared bounded framing/process cleanup lives in `native_queue_connection.rs`; request deadlines belong to `queue_budget.rs`, with compatibility reexports from import. New job kinds must not depend on import DTOs. Engine `desktop_queue_service.rs` holds an infrastructure kernel lease and fixes scope to `desktop-import`. Never delete `.desktop-import-executor.lock` or expose queue through metadata IPC. Keep grants/receipts out of renderer DTOs. Scoped claims obey global resource limits; scope is not a process lease. Explicit native `Run` now owns import threads until cancel/join; policies and contracts live in `application/import_execution.rs` and `import_ports.rs`. Preserve logical receipt IDs on retry and fence ledger writes by attempt. Native queue open reconciles all receipt pages before returning; policies live in `application/import_recovery.rs`. Recovery only probes receipts, never copies/retries; preserve unknown outcomes and compare observed records before writes. File-picker UI uses `queued_import.rs` through `ImportQueueSession`; shared request budgets observe cancellation during RPC and stop/reap before receipt fallback. Progress is fractional. Recorder takes an injected `capture_backend.rs` port; OS selection lives in `capture_platform.rs`, Windows in `capture/windows.rs`, Linux microphone in `capture/linux.rs`, shared PCM/WAV in `capture_audio.rs`. Driver callbacks never mutate Recorder state. IPC supplies recordingModes from the managed backend; metadata-only Bridge advertises no device capture. Stop/recover use `recording_import.rs` through CapturedRecording/RecordingLibrary ports; capture UUID is the stable operation ID, private token lives in the canonical queue. Find-by-object rejects ambiguity; probe receipts before WAV repair. `capture/guard.rs` holds `.capture-session.lock` through capture/import and explicitly unlocks on Drop; never delete it. `recordingRecovery` is independent of hardware recording. See `docs/decisions/durable-recording-import.md`. `import_history.rs` maps private DTOs to grant-free renderer history (50 rows/page, immutable creation-time + ID cursor). Startup/history reads reconcile without resuming; explicit resume/cancel use expectedAttempt. `Imports.reserve()` serializes maintenance/startup, and fresh controlId fences live cancellation across retries. UI serializes history/recovery maintenance reads and coalesces identical in-flight pages. Preserve `float_roundtrip` for exact timestamp cursors; SQL history reads tolerate legacy one-ULP payload rounding without writes. See `docs/decisions/import-history-pagination.md`. Defer destructive actions and Swift removal until approved after parity. Main 0.18.3 material filters/origins are integrated; `domain/creation_origin.rs` owns immutable provenance and the SQL adapter preserves it across raw writes/undo. ## Data & Trust Boundaries

Use disposable libraries, synthetic providers and explicit feature grants. Source read access does not authorize cloud upload. Preserve C ABI/JSON, CAS, atomic receipts, unknown compatible fields and current-source checks. Keep credentials out of logs, fixtures, queue and process arguments. Never weaken runtime/model/library integrity checks to pass tests. Python does not own canonical SQLite. Swift platform contracts must not depend on AppStore; check `scripts/check_platform_boundaries.py` (Swift package graph requires Swift 6).
