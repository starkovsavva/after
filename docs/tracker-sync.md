# Синхронизация задач

«После» получает задачи из выбранных списков Google Tasks и очередей Яндекс Трекера. Отправка изменений включается отдельно. Подключения по умолчанию отсутствуют; приложение не использует аккаунты календаря, браузера или macOS.

## Подключение

Откройте **Настройки → Интеграции → Трекеры → Подключить**. Назовите аккаунт, добавьте токен, загрузите доступные списки и отметьте нужные. Включите автоматическую синхронизацию. Отправку изменений можно разрешить позднее.

**Google Tasks.** Нужен OAuth access token с разрешением `https://www.googleapis.com/auth/tasks` для обмена в обе стороны или `https://www.googleapis.com/auth/tasks.readonly` для получения. Укажите время окончания действия токена. Для автоматического продления раскройте «Продление доступа Google» и добавьте client ID своего OAuth Desktop-приложения, refresh token и client secret, если он выдан. Google Tasks API должен быть включён в вашем проекте Google Cloud. Готовый общий OAuth-клиент в приложение не вшит; браузерный вход без своего клиента пока не предоставляется.

При выпуске refresh token OAuth-клиент должен запросить доступ к Tasks и offline access. Настройка consent screen и статус приложения могут влиять на срок действия refresh token. См. [OAuth для установленных приложений](https://developers.google.com/identity/protocols/oauth2/native-app), [обновление access token](https://developers.google.com/identity/protocols/oauth2/native-app#offline) и [разрешения Tasks API](https://developers.google.com/workspace/tasks/auth).

**Яндекс Трекер.** Добавьте OAuth-токен с `tracker:read` и, для отправки, `tracker:write`. ID организации находится в администрировании Трекера. Для Яндекс 360 используется обычный ID организации; для Yandex Identity Hub включите соответствующий переключатель. IAM-токен поддерживается только для Identity Hub: включите IAM и укажите срок действия. Автоматический выпуск нового IAM-токена не выполняется. См. [официальную инструкцию доступа](https://yandex.ru/support/tracker/ru/api/access).

Токены, client secret и refresh token хранятся в Связке ключей этого Mac. В журнале остаются только параметры подключения, сроки и сопоставления задач. Отключение удаляет секреты и останавливает обмен, сохраняя локальные задачи и материалы. Другой аккаунт подключается отдельной записью, чтобы его данные не смешивались со старыми сопоставлениями.

## Работа с задачами

Полученные задачи появляются в обычном трекере «После». Синхронизируются название, описание, срок и статус; для Яндекс Трекера — также ID ответственного. Google Tasks поддерживает только «К выполнению» и «Готово»: локальные «В работе» и «Ожидает» сохраняются в «После».

Для новой локальной задачи выберите **… → Отправить в трекер…**, аккаунт и список. Перед отправкой видны назначение и состав полей. Существующие импортированные задачи связываются по постоянному ID. Материалы, приватные мысли, история агента, файлы и записи встреч в провайдера не отправляются.

В Яндекс Трекере настраиваются ключи четырёх статусов. Изменение статуса использует доступный переход рабочего процесса; неоднозначный или недоступный переход требует действий в самом Трекере. Дополнительные обязательные поля перехода автоматически не подставляются. Срок должен быть записан как дата `ГГГГ-ММ-ДД`; произвольная фраза не превращается в дату без проверки.

Если одна задача изменилась с обеих сторон, откройте сравнение в настройках и выберите локальную или внешнюю версию. Перед применением обе версии проверяются заново. Удаление автоматически не передаётся: копия сохраняется, а разорванная связь не восстанавливается следующим импортом.

При HTTP 429 учитывается `Retry-After`, при временных ошибках действует задержка повторов. При 401 требуется обновить доступ. Фоновая проверка выполняется примерно раз в пять минут, когда приложение свободно; её можно поставить на паузу. Кнопка синхронизации запускает проверку вручную.

## Повторы и ограничения

Перед внешней записью сохраняется намерение операции. После обрыва соединения приложение сначала сверяет результат. Google Tasks не предоставляет ключ идемпотентности для создания: в описании новой задачи сохраняется служебная метка. Если результат создания пока не найден, повторный POST блокируется, чтобы не получить дубликат. Неподтверждённая операция остаётся в очереди и проверяется снова; это может потребовать ручной проверки списка, если провайдер не выполнил исходный запрос. Яндекс Трекер поддерживает поле `unique`, и повтор с тем же ключом не создаёт вторую задачу.

Импорт ограничен 9000 задачами за выбранные списки. Все страницы получения загружаются до изменения локальной библиотеки; незавершённая выборка не приводит к удалению задач. Для очень больших очередей используйте отдельный список меньшего размера. Фоновый обмен работает, пока «После» открыто.

Проверки выполняются на локальных HTTP-стендах без пользовательских токенов и аккаунтов. Они покрывают получение всех страниц, условную запись, конфликт, удаление, потерю ответа при создании, повтор без дубликатов, истёкший доступ и ограничение частоты. Живой вход в ваши аккаунты не выполнялся.
