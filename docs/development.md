# Разработка

[Архитектура базы знаний и помощника](architecture.md) — границы чтения, действий, индексов и фоновой обработки.

Нужны Apple Silicon, macOS 15+, Swift с SDK macOS 26+, Rust и Python 3.12.
Системный Liquid Glass применяется на macOS 26; на macOS 15 используется
матовое стекло. Снижение прозрачности и повышенный контраст имеют приоритет.

```bash
bash scripts/setup-rust.sh
python3 -m venv .test-data/checks
.test-data/checks/bin/python -m pip install numpy==2.2.6 imageio-ffmpeg==0.6.0
export POSLE_PYTHON="$PWD/.test-data/checks/bin/python"
python3 scripts/verify.py quick
bash scripts/build.sh
```

`verify.py --list` показывает профили:

- `quick`: сборка SwiftUI, SwiftPM core tests, Python contracts, Rust tests.
- `integration`: Rust CLI/C ABI, локальные HTTP-стенды, синтетическое аудио/видео, поиск и миграция модельной среды.
- `native`: SwiftUI и NSApplication в отдельных временных библиотеках. Нужна активная графическая сессия Mac; сценарии запускаются последовательно.
- `release`: все перечисленные проверки и настоящий Sparkle SDK на одноразовых подписанных приложениях. Ничего не публикует и не использует ключ подписи «После».

```bash
python3 scripts/verify.py integration
python3 scripts/verify.py native
python3 scripts/verify.py release --sparkle-root .build/artifacts/sparkle/Sparkle
```

Каталоги сборки можно задать через `POSLE_BUILD_DIR` и `POSLE_RUST_TARGET_DIR`.
Core-проверки запускаются через SwiftPM/XCTest; с Command Line Tools — через `swiftc`.

`POSLE_PYTHON` выбирает тестовый Python; личная установленная библиотека приложения
не используется по умолчанию.

Проверки создают собственные временные данные. Они не захватывают микрофон/экран,
не подключают календари, не читают существующие встречи и не вызывают платные API.
Нейросетевое качество распознавания проверяется отдельно с явно выбранными весами:
`--preview --check-embedded-speech --embedded-root "$PWD/.test-data" --full-flow`.
Реальный аудиофайл проверяется вручную в отдельной тестовой библиотеке с заранее
подготовленными моделями и средой распознавания:

```bash
"$POSLE_PYTHON" scripts/check_audio.py \
  --source "/absolute/path/meeting.mp3" \
  --root "$PWD/.test-data/audio-check" \
  --seconds 75 --offset 0 --speakers 0
```

`--speakers 0` определяет число участников автоматически; можно указать точное число.
Этот запуск не входит в автоматические профили и не использует личную библиотеку приложения.

## Целостность компонентов

Release загружает Rust-ядро из своего bundle. SHA256 окончательно подписанной
библиотеки встроен в executable (`__TEXT/__posle_core`) и проверяется до `dlopen`.
Переопределения `POSLE_RUST_LIBRARY` и `POSLE_RUST_ENGINE` работают только в DEBUG.
Shell startup-переменные и overrides загрузчика не передаются дочерним процессам.

CPython закреплён точным архивом в `backend/python-runtime.json`. Полный инвентарь
файлов и внутренних ссылок встроен в Rust; оба Python host проверяют его до загрузки.
Установщик проверяет архив и дерево до первого запуска Python, затем создаёт новую
venv с откатом при ошибке. Неподходящие компоненты требуют повторной подготовки;
записи и кеш моделей сохраняются. Инвентарь воспроизводится без выполнения архива:

```bash
python3 scripts/pin_python_runtime.py --archive /absolute/path/pinned-python.tar.gz --check
```

Это защита закреплённого CPython и Rust-библиотеки. Установленные pip-пакеты остаются
отдельной границей доверия: полного hash lock для MLX/ONNX и транзитивных зависимостей
пока нет. Хеш-проверка не гарантирует защиты от процесса того же пользователя,
одновременно переписывающего уже открытый inode; доверенное приложение и ограничения
macOS остаются частью модели угроз.

Media/native стенды явно допускают другой тестовый Python только DEBUG-ядру и во
временных `posle-*` каталогах. Release игнорирует этот тестовый флаг.

## Границы кода

- `Sources/PosleApp`: SwiftUI/AppKit, устройства, календарь и координация действий.
- `Sources/PosleCore`: чистые модели, календарная геометрия и форматирование.
- `Sources/PosleApp/Diagnostics`: только DEBUG-сценарии с настоящим UI. Они остаются
  в модуле приложения для доступа к его жизненному циклу; release-сборка их исключает.
- `Tests`: SwiftPM-проверки PosleCore; `UpdateFixture.swift` — отдельное приложение
  для реального Sparkle E2E, не часть production app или core test target.
- `rust-core`: хранилище, поиск, AI-запросы, карточки и атомарные операции.
  Домен `task_workspace` хранит связи материалов, историю, снимки контекста и
  блокировки задач в той же транзакции, что и заметки. SwiftUI, голосовые поручения
  и MCP вызывают эти операции с проверкой ревизий; отдельных копий трекера нет.
- `backend`: встроенный CPython для ASR, разделения голосов и медиа.

Очередь хранится в приватной SQLite-базе `jobs.sqlite`. Rust атомарно меняет
состояния, Swift actor управляет исполнителями: одна тяжёлая локальная операция,
до двух облачных и двух лёгких. У задания свой снимок настроек, ревизия входных
данных, отмена и номер попытки. Прерванные платные запросы требуют явного повтора.

Обновления работают через Sparkle с подписанным feed и
[Gentle Reminders](https://sparkle-project.org/documentation/gentle-reminders/).
Плановая проверка показывает действие в приложении; установка ждёт окончания
записи и обработки, закрытия редакторов и сохранения черновиков. Bundle ID
`app.posle.meetings` и путь `/Applications/После.app` сохраняются между версиями.

По умолчанию `build.sh` использует ad-hoc подпись для разработки: разрешения
macOS могут потребовать повторного подтверждения после обновления. Для стабильной
идентичности укажи fingerprint своего сертификата `Developer ID Application`
(для распространения) или `Apple Development` (для разработки):

```bash
POSLE_CODESIGN_IDENTITY="40-значный SHA-1 fingerprint сертификата" bash scripts/build.sh
```

Скрипт проверяет выбранную identity до сборки и сохраняет стандартные требования
Apple к подписи. Сертификат не выбирается автоматически; ключи и доверие не
изменяются. Нотариализация — отдельный этап, эта настройка её не выполняет.

`build.sh` собирает приложение, `package.sh` упаковывает проверенный bundle,
`publish_release.py` публикует проверенные неизменяемые артефакты и подписанный feed.
Эти этапы не заменяют проверки. Базовый macOS build и `quick` запускаются в GitHub Actions.

Собственный код распространяется по [MIT](../LICENSE). Модели и сторонние
компоненты сохраняют свои лицензии: [THIRD_PARTY.md](../THIRD_PARTY.md).

## MCP задач

Встроенный `posle-engine mcp --root /absolute/library/path` работает по stdio
через официальный Rust SDK. Настройки подключения копируются из
«Настройки → Интеграции». Приложение не редактирует конфигурацию Codex.
MCP выключен по умолчанию; доступ дополнительно задаётся у каждой задачи
и материала. Папки и репозитории передаются как ссылки, без обхода файлов.

Чтение контекста возвращает `revision` и `contextVersion`. Агент получает
`claimID`, сохраняет отчёт и только после этого завершает задачу. Каждый
запрос записи имеет `operationID`: одинаковый повтор не создаёт дубликаты,
другая полезная нагрузка с тем же ID отклоняется. Новый контекст требует
повторного чтения перед завершением. Сквозной `scripts/check_mcp.py` проверяет
настоящий процесс MCP на одноразовой библиотеке без аккаунтов и моделей.
