# Поиск ответы и навигация через помощника After

Дата: 30 октября 2026 года. Статус: дополнение к
[спецификации базы знаний](knowledge-base.md). Джарвис здесь — встроенный помощник
After, действующий по прямому запросу пользователя. Этот документ описывает
проверенную основу, недостающие контракты и приёмку; реализация и релиз не выполняются.

Совместная поставка с базой знаний и проверка кандидата — в
[плане интеграции](knowledge-release-plan.md).

## 1. Основной пользовательский сценарий

Пользователь говорит или пишет:

> «Что там в последней таске?» → получает задачу, статус, последний результат
> и источники → «Открой её» → открывается именно эта задача.

Тот же путь поддерживает заметку, запись встречи, реплику, календарное событие и
артефакт задачи. Помощник показывает, что он нашёл и почему выбрал именно это.
Простая навигация не требует подтверждения изменения данных.

Текст и голос приводятся к одному AssistantRequest. Голос использует существующую
явную диктовку и её разрешение микрофона; отсутствие доступа оставляет текстовый
ввод доступным. Переход к источнику не запускает запись. Для голосового запроса
queryNow фиксируется при завершении пользовательской реплики, до задержки ASR.
Редактирование относительного запроса и новая отправка формируют новый request clock.

| Запрос | Ожидаемое действие |
| --- | --- |
| «Найди заметку про задержку API» | Найденные заметки с названием, кратким совпадением и кнопкой открытия |
| «Открой встречу про запуск, которая была вчера» | Точная запись встречи либо выбор между подходящими вариантами |
| «Что в последней задаче?» | Явно выбранная по правилу времени задача, текущие поля, последний релевантный отчёт и артефакты |
| «Что агент сделал в последней задаче?» | Сначала последняя задача по принятому правилу, затем её последний report, с атрибуцией исполнителю |
| «По какой задаче агент последним отчитался?» | Задача с последним report в выбранной области, затем этот отчёт |
| «Когда у меня встреча с Сергеем?» | Дата и время из подключённого календаря, покрытие поиска и переход к occurrence |
| «Что у меня по задачам на сегодня?» | Выборка по каноническому сроку до ограничения выдачи; просроченные обозначены отдельно |
| «Что решили про онбординг?» | Краткий ответ с переходами к решениям и исходным репликам |
| «Что посоветуешь проверить перед запуском?» | Подтверждённые факты и отдельно рекомендации с основаниями |
| «Открой её», «Покажи этот отчёт», «Вторую» | Проверяемая ссылка текущего разговора или показанного списка |

Обычный вопрос отвечает и предлагает переход. Явное «открой» открывает один
однозначный объект сразу. «Найди» показывает результаты. Несколько подходящих
объектов требуют выбора с датами и папками; отсутствие совпадения даёт уточнение,
а не выдуманный объект. Составной запрос «расскажи и открой» допускает только
ограниченную последовательность `ask → open`, с сохранением ответа в интерфейсе.

## 2. Что подтверждено текущим кодом

| Путь | Текущее поведение и ограничение |
| --- | --- |
| [voice.rs](../../rust-core/src/voice.rs) | Классификация `askKnowledge`, `openTask/openNote/openMeeting/openCard`; вопрос не становится mutation plan. Отдельных intent `find` и `recommend` пока нет. |
| [library_intents.rs](../../rust-core/src/voice/library_intents.rs) | До 20 реальных кандидатов, reranking по supplied IDs, `ready/choose/unsupported`, проверка перед открытием. |
| [task_intents.rs](../../rust-core/src/voice/task_intents.rs) | До 24 кандидатов задач, выбор и typed navigation. Selected task, relevance и updatedAt влияют на shortlist; это не selector «последняя». |
| [knowledge.rs](../../rust-core/src/knowledge.rs) | Поиск, текущие поля задачи и ответы с проверяемыми citations. История и артефакты задачи сейчас не являются источниками ответа. |
| [VoiceCommands.swift](../../Sources/PosleApp/VoiceCommands.swift) | Ответ → открыть источник; повторная проверка и request generation. Follow-up хранит темы пользовательских вопросов, но не точную ссылку для «открой её». |
| [KnowledgeSourceNavigation.swift](../../Sources/PosleApp/KnowledgeSourceNavigation.swift) | Native маршруты для задачи, заметки, встречи/фрагмента и календарной цитаты; URI не генерируется моделью. |
| [CalendarStore.swift](../../Sources/PosleApp/CalendarStore.swift) | Снимок уже подключённых/видимых календарей, до 128 событий и 128 KiB; обычно −7/+31 день либо распознанный период. Переход к конкретному occurrence. |

Открытие не меняет найденный объект, его статус или доступ агенту. Существующий
open-путь может сохранять служебный voice plan; это отличается от изменения задачи.

На текущем рабочем дереве выполнены 67 существующих Rust-тестов:
`knowledge::tests` — 21, `voice::tests` — 32,
`voice::task_intents::tests` — 12, `voice::library_intents::tests` — 2.
Все прошли на временных библиотеках и localhost fixtures.

Проверены маршрутизация, read-only поведение, scopes, citations, устаревание,

не проверялись. Зелёные тесты не доказывают выбор «последней задачи», чтение
последнего артефакта или правильное обоснование совета — это новые cases ниже.

## 3. Контракт запроса и результата

Native-код формирует запрос, фиксируя время до классификации:

```json
{
  "text": "Что агент сделал в последней задаче?",
  "requestGeneration": "opaque-request",
  "scope": {"mode": "library", "folderID": null, "projectID": null},
  "clock": {"queryNow": 1793386800, "timeZoneID": "Europe/Moscow"},
  "continuationID": null
}
```

Предлагаемый `AssistantReadPlan`:

```text
intent = find | open | ask | recommend
entityKind = task | note | meeting | transcript | card | calendar | taskEvent | taskArtifact
selector = search(query) | exact(verifiedRef) | latest(axis, filters) | timeRange(range)
scope = native-validated library/folder/project scope
continuation = optional reference to the current conversation or candidate set
```

Результат содержит `state=results|answer|clarify|notFound|unavailable`,
`selectionExplanation`, targets, факты с citations, необязательные рекомендации,
coverage, warnings и asOf. Поиск/сортировка/лимиты исполняются доменом, а не
выбором LLM «самого последнего» из случайного bounded списка.

Модель выбирает только supplied IDs и enum-параметры. Она не создаёт пути,
URL схемы приложения, произвольные команды открытия или новые права.
Классификатор read/navigation-ветви не получает возможность записать изменения.
Явное создание/изменение/удаление остаётся существующим отдельным workflow с
предпросмотром и подтверждением; вопрос не превращается в него автоматически.

Точное имя/ID, typed recency и время обслуживаются structured/lexical retrieval
без embeddings. Детерминированное «открой выбранный результат» не требует второго
LLM-вызова. Отсутствие модели оставляет такой поиск доступным; синтез ответа
показывает состояние недоступности, без перехода в облако.

Для этого J1 добавляет deterministic entry point: режим поиска и закрытую
грамматику явных команд найти/открыть, выбора результата и temporal selectors.
Нельзя оставить обязательный LLM-классификатор перед каждым lexical lookup.
Непонятная формулировка без модели остаётся поисковым текстом/уточнением, а не
угадываемой командой изменения.

## 4. Что означает последняя задача

Нужно добавить selector до pagination и candidate caps:

| Фраза | Ось и правило |
| --- | --- |
| «Последняя созданная», по умолчанию «последняя задача» | `createdAt DESC` только с достоверным происхождением даты; явно написать «Последняя созданная задача» |
| «Последняя добавленная в After» | `addedAt DESC` / наблюдавшееся первое появление в библиотеке |
| «Последняя изменённая мной» | `lastContentEditAt DESC`, без технического обновления из progress/report |
| «Последняя, по которой агент отчитался» | `latestReportAt DESC` по реальным report events |
| «Над чем агент сейчас работает?» | Активный claim/run, текущий progress; не выдавать его за завершённый отчёт |
| «Последняя открытая» | Native `lastOpenedAt`, если такая история доступна |
| «Эта задача», «она» | Точный referent разговора либо явно указанного пользователем открытого объекта |

`task-list.updatedAt` не заменяет все эти оси: progress/report/completion обновляют
его у старой задачи. Повышение релевантности и выбранная вкладка также не меняют
результат typed selector.

У виртуальных задач конспекта текущий createdAt — дата встречи. Его нельзя выдавать
за реальный момент создания задачи. Адаптер должен возвращать provenance даты
(`nativeCreation`, `providerCreation`, `meetingDate`, `firstObserved`, `unknown`).
Неизвестные даты не заполняются временем migration/reindex. Если нельзя сравнить
всю запрошенную область, помощник обозначает покрытие или предлагает выбор,
например «последняя созданная» / «последний отчёт», без ложной общей хронологии.

При равных временных значениях backend сортирует стабильно по UUID; если равенство
меняет смысл выбора одной задачи, UI показывает варианты. «За сегодня» сначала
фильтрует canonical due date в заданной зоне, затем применяет limit; top-10
релевантных задач не считается полным списком задач со сроком на сегодня.

## 5. История и артефакты как native источники

Нужен `TaskHistorySourceAdapter`, читающий существующие task records без изменения
claims или статуса. Текущий `task-context` намеренно исключает history; расширять
его выдачу внешним агентам ради native помощника не требуется.

```text
TaskEventRef = { taskID, taskEventID, contentRevision }
TaskArtifactRef = { taskID, taskEventID, artifactID, contentRevision }
```

Добавить явные поля в KnowledgeSource/typed route; календарный eventID остаётся
идентификатором календаря. Fingerprint строится по конкретному event/artifact и
его dependencies. Task contextVersion, исключающий history, для этого недостаточен.
Swift/Rust feature policy должна разрешать новые `taskEvent/taskArtifact` только
при доступности tasks; неизвестный kind по-прежнему отклоняется.

Короткий ответ по задаче: название и основание выбора, статус, указанные срок и
ответственный, последний релевантный отчёт, до трёх артефактов. Полный отчёт
читается отдельно bounded read; ограничения и truncation видны пользователю.
За один retrieval передаётся до десяти подходящих events одной задачи; excerpt
одного артефакта — до 8 KiB с UTF-8-safe spans. Сначала выбирается правильный
последний event по оси времени, затем применяется лимит. Генерация сохраняет
общий prompt budget основной спеки; открыть полный артефакт можно без передачи
его целиком в модель.
«Агент сообщил, что проверки прошли» сохраняет атрибуцию — наличие отчёта само по
себе не подтверждает исполнение проверки независимым инструментом.

Native маршрут открывает точную вкладку Истории, event или artifact sheet.
Исходники и derived lineage проверяются перед показом и переходом. Это on-demand
чтение текущей истории, не включение артефактов в автоматический граф доказательств.
Правила redaction, stale sources и повторной выдачи из основной спеки сохраняются.

## 6. Продолжение разговора и открытие

Расширить существующие previous USER questions отдельным ephemeral
`ConversationTargets`: session/library ID, до шести проверенных refs, source
fingerprints, scope fingerprint, candidateSetVersion и время. Максимальный срок
без активности — 30 минут; смена библиотеки, reset и закрытие разговора очищают refs.
Ответ LLM не становится фактом; referent хранит только указатель на реальный объект.

Native добавляет referent после проверенного результата или выбора пользователя.
«Открой её» разрешается без новой генерации, если референт один. «Вторую» привязано
к версии реально показанного списка; старый или пересортированный список не
используется по индексу. Несколько правдоподобных refs дают выбор, ноль — короткое
уточнение. Старая команда изменения никогда не исполняется из continuation.

Перед навигацией проверяются generation, текущая библиотека, permissions,
feature/profile, fingerprint и target. Результат закрытого/отменённого запроса
не открывает экран позднее. Навигация проходит через существующее сохранение
черновиков: невозможность сохранить оставляет редактор и введённый текст на месте.
Отдельные approval sheets для простого чтения и открытия не добавляются.

## 7. Когда у меня и календарные вопросы

Различать начало события календаря, срок задачи, дату записи встречи и упомянутую
в тексте дату. Срок без времени не превращается во встречу на выдуманный час.
При совпадении названий показывать тип источника; запись встречи и будущее событие
не объединяются только из-за одинакового заголовка.

`queryNow + IANA timeZoneID` фиксируются при отправке. Relative range разрешается
один раз native Calendar API; свежий snapshot после классификации использует тот
же период. Если модель отвечала через полночь, «завтра» не переносится ещё на день.
`validationNow/asOf` отдельно обозначают свежесть данных. Период передаётся Rust
каноническими start/end epochs, без повторного вычисления через один FixedOffset.

Границы дней/недель учитывают DST. All-day событие сохраняет календарные даты и
не получает время. Для «ближайшей встречи» сначала выбираются текущие события,
иначе ближайший будущий start; при равных вариантах — список. Прошедшее событие
не побеждает только потому, что оно ближе к now по абсолютному расстоянию.

`CalendarKnowledgeSourceAdapter` возвращает свежий immutable snapshot через
worker/actor-путь, переиспользуя CalendarReadClient. Длительное чтение EventKit
не расширяется на main thread. Сохраняются выбранные календари, текущий вид и
выбранный в календарном UI период; запрос помощника их не переключает.

В ответе обязательны authorization/connection state, coverage и truncated.
Проверка ограниченного диапазона не даёт права говорить «такой встречи нет».
Отозванное разрешение/отключённый календарь не вызывают системный prompt скрытно.
Переход по источнику повторно проверяет конкретный occurrence, доступ и fingerprint.

## 8. Совет по базе знаний

`recommend` разделяет:

- `facts`: что найдено, с SourceRefs и версиями;
- `suggestions`: предлагаемый следующий шаг, его основания и существенные допущения.

Рекомендация не изображается принятым решением, известным фактом или выполненной
задачей. Например, найденные открытые вопросы могут обосновывать предложение
проверить доступ к стенду; они не доказывают, что доступ сейчас сломан.
Если оснований нет, помощник сообщает это и может дать явно общий совет.

Совет не создаёт задачу, событие или связь сам. Действие «Создать задачу из совета»
сохраняет текст как новый явный пользовательский запрос, после чего работает
обычный preview/apply. Инструкции в источниках не расширяют полномочия помощника.

## 9. Разрешения и независимость от внешнего агента

Native Джарвис действует от пользователя: task grant, claim и MCP run ему не
требуются. Сохраняются `assistant`, tasks/calendar/другие feature gates, профили,
явная область и разрешения выбранного провайдера. Вопрос по библиотеке по умолчанию
использует доступную библиотеку; выбранная задача не становится скрытым фильтром.
Узкая область показывается отдельным chip и задаётся явно пользователем.

Существующие ответы и поиск не требуют включения будущего `knowledgeBase`.
Автоматические темы доступны при включённой соответствующей функции. Отсутствие
semanticSearch оставляет FTS/structured путь и не запускает embedding модель.
Выключенный модуль не включается по одной фразе; предлагается явный переход в настройки.

Классификация также является provider call: если облачная передача вопроса и
контекста не разрешена, она не выполняется. Разрешённый локальный/детерминированный
путь остаётся доступным. Все новые модельные этапы подчиняются общему lease,
bounded generation API и бюджету основной спеки.

Внешние Codex/Claude/MCP-клиенты сохраняют отдельные task-bound grants. Native
доступ помощника к истории не расширяет scope или набор tools внешнего клиента.

## 10. План доработки и приёмка

| Этап | Изменения | Зависимость |
| --- | --- | --- |
| J1 | ReadPlan, find/open/ask, typed selectors, явный scope, замороженное время и lookup без embeddings | Существующий domain; можно делать до автоматического графа |
| J2 | TaskHistorySourceAdapter, artifact/event routes, ConversationTargets, recommend и native calendar worker | J1 и контракты происхождения/доступа основной спеки |
| J3 | Ответы по автоматически собранным темам и интеграция сквозного сценария | Готовые и проверенные темы из этапа 3 основной спеки |

Обязательные новые проверки:

1. Точное название находится без generative/embedding-модели; scope и feature gates сохраняются.
2. Единственный open target открывается; два одинаковых названия дают выбор с датой и папкой.
3. Новая созданная задача выбирается раньше старой с новым progress/report; дата виртуальной задачи не выдаётся за creation time.
4. «Что агент сделал в последней задаче» выбирает отчёт внутри последней созданной
   задачи; «по какой последним отчитался» может выбрать другую задачу. Последний
   event выбирается до лимита; атрибуция и переход к точному artifact сохраняются.
5. Все задачи со сроком на сегодня отбираются до retrieval caps; просрочка и неоднозначный legacy due не теряются/не угадываются.
6. Due задачи, календарный start, дата записи и цитируемая дата не смешиваются.
7. Полночь во время классификации, DST, смена системной зоны и all-day сохраняют определённый период.
8. Прошедшее событие не подменяет ближайшее будущее; неполное покрытие не даёт ложного «ничего нет».
9. «Открой её» после ответа и «вторую» после списка открывают проверенные refs; stale candidate set даёт уточнение.
10. Правка/Trash/отзыв, смена библиотеки, отмена и закрытие панели запрещают поздний переход.
11. Несохранённый редактор остаётся целым при неудачном сохранении перед навигацией.
12. Отключённый календарь/assistant/tasks, отсутствие cloud consent и embedding failure не вызывают скрытого включения или отправки.
13. Совет отделён от фактов; injection остаётся данными; ни совет, ни find/open не меняют найденный объект.
14. Native SwiftUI flow: вопрос → ответ → уточнение → источник/История → artifact → исходный материал, включая клавиатуру и RU/EN.

Детерминированные fixtures проверяют маршрутизацию и ограничения. Отдельный
небольшой набор реальных RU/EN-формулировок проверяет classifier/retrieval на
разрешённой модели: сокращения «таска», неполные названия, опечатки и follow-up.
Результаты фиксируются раздельно; синтетический PASS не заменяет модельную оценку.
Реальные личные данные, календарные подключения и платные вызовы не включаются
в автоматические проверки по умолчанию.
