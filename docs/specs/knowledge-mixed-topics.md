# Темы с заметками и встречами

Статус: реализованы в локальной сборке, без публикации релиза. Раздел базы знаний показывает отдельный блок «Встречи и заметки по темам». Это предложения для просмотра: они не перемещают оригиналы, не создают постоянные связи сами и не передают материал внешнему агенту. Сохранённые подборки заметок работают отдельно.

## Контракт источников и прав

Связь указывает на **версию опубликованного содержания**, а не на файловый экземпляр. Для заметки проверяются ID, ревизия и отпечаток. Для материала встречи — ID встречи, вид источника, ID реплики либо индекс пункта и точный хеш опубликованного файла. Конспект допускается только при актуальной зависимости от транскрипта. Индекс пункта без хеша недостаточен.

Удаление встречи делает её материал недоступным. Восстановление тех же байтов под тем же ID восстанавливает ту же версию содержания, если текущие права позволяют её читать. Это намеренный контракт, а не попытка отличить восстановление резервной копии от повторного создания идентичного документа. Привязка к inode, глобальный журнал всех старых писателей и изоляция всей библиотеки для этого не нужны.

Явное удаление ручной связи сохраняет tombstone в `kb_meeting_links`. Восстановление источника и повтор старой операции добавления не отменяют его. Только новое явное добавление или допустимая отмена удаления могут вернуть связь. Отмена проверяет текущую версию обоих концов и не перезаписывает более позднее изменение.

При каждом чтении и открытии проверяются текущая область и разрешение базы знаний. Старый `policyFingerprint`, сохранённый прежней сборкой, не является идентичностью содержания: смена модели не ломает неизменную ссылку. Политика разрешения читается заново. Недоступная сохранённая связь возвращает только свой ID и ревизию для удаления, без ID встречи, названия или текста. Обратные ссылки показываются только при доступности обеих сторон.

Нативная выдача — локальный снимок с перепроверкой перед возвратом и при переходе. Она не обещает атомарность с произвольным процессом того же пользователя, меняющим файлы между проверкой и отрисовкой. Уже прочитанные данные нельзя «отозвать из памяти» другого приложения. Отдельный MCP использует свой контракт явно опубликованных копий; этот индекс не даёт агенту никаких прав.

## Индекс и формирование тем

1. `knowledge_mixed_inventory` обходит членство каталога встреч страницами по 16 записей. Возобновляемая контрольная точка находится в `knowledge-mixed-index/meetings-<scope>.sqlite`; она хранит только ID и хеши, без названий и текста. Каталог/файлы приватные, симлинки и неподходящая версия базы отклоняются. При изменившемся составе или содержании перестраивается только производный индекс.
2. Перед выдачей проводится полная сверка доступных материалов с индексом. Отсутствующие, повреждённые, ещё записываемые и обрабатываемые встречи не участвуют. Некорректный источник не мешает доступным источникам; результат отмечается неполным. Файловые события не считаются единственным источником истины.
3. Одна встреча представляет один узел. Предпочтение отдаётся актуальному конспекту; иначе используется ограниченное представление транскрипта с признаком неполноты. Длинная встреча не получает сотни отдельных голосов. Точная ссылка на её доступный материал хранится для открытия, но не выдаётся за доказательство каждого смыслового сходства.
4. Семантические центроиды берутся только из завершённого текущего поколения общего `semantic` индекса. Используются до четырёх чанков заметки и до шестнадцати чанков транскрипта/конспекта встречи, без векторов одного заголовка. Отпечатки источников, разрешение `semanticSearch` и manifest модели проверяются. Этот шаг не запускает модель и не делает сетевой запрос.
5. До 250 узлов сравниваются все пары. Затем используется ограниченный лексический индекс и соседи по двенадцати детерминированным проекциям; окончательный балл всегда считается точным cosine. У каждого узла остаётся до восьми соседей. Группа содержит не более шести узлов, каждая пара которых согласована в обе стороны: транзитивный мост не объединяет разные проекты в одну тему.
6. Для встроенного `qwen3-embedding:0.6b`, revision `qwen3-embedding-0.6b-06507c7b-llama-v0.40.3-cpu-v1`, 1024 измерений и пустого document prefix порог равен **0.58**. Он выбран на отдельной калибровочной выборке до запуска holdout. Для другого manifest действует консервативный порог 0.82. Известное смысловое несоответствие блокирует случайное совпадение слов. При отсутствии актуальных векторов используется явно подписанное совпадение общих слов.
7. Заголовок темы составляется из общих терминов; это не сгенерированное моделью название. Интерфейс различает «по смыслу», «по общим словам» и смешанный способ. ID темы — хеш отсортированного состава типизированных узлов; `note:x` и `meeting:x` различаются.

### Явные ограничения текущей версии

| Область | Ограничение и поведение |
| --- | --- |
| Состав для группировки | До 2000 узлов, включая до 1000 встреч; типы чередуются, чтобы заметки не вытеснили все встречи |
| Смысловые векторы | До 1000 разрешённых узлов, также с чередованием типов |
| Текст встречи для лексики | До 16 000 байт; отсутствие актуального конспекта или обрезка означают частичное представление |
| Соседи и группа | До 8 соседей и 6 участников; после 250 узлов поиск кандидатов приблизительный |
| Страница тем | 40 групп, формируемых до пагинации; новая страница заново проверяет текущий срез и заменяет предыдущую |
| Кнопка ручных подсказок в заметке | Существующий отдельный поиск до 100 встреч/2000 материалов; это не предел нового смешанного индекса |
| Постоянные смешанные подборки | Не создаются автоматически; постоянная связь заметки с материалом встречи сохраняется отдельным явным действием |

При достижении ограничений показываются число рассмотренных/доступных материалов и предупреждение о возможных пропусках. Это не полный граф всех возможных связей и не автоматическая архитектура всей библиотеки. Подборки заметок, ручные ссылки и решения пользователя не заменяются предложениями.

## Нативный API и жизненный цикл

- `kb-mixed-topics`: текущая область `folderID`, `requestID` для отмены, offset страницы. Возвращает темы с типизированными источниками, точными версиями, методом, числом рассмотренных материалов, семантическим покрытием и признаком неполноты.
- `kb-mixed-topics-cancel`: отмена конкретного запроса, включая отмену до регистрации worker. Этот канал не отменяет отдельную обработку тем только из заметок.
- `kb-topic-source-validate`: повторная проверка выбранного узла перед открытием. Для встречи проверяется соответствие вложенного якоря тому же ID и опубликованному представлению; подмена другим допустимым источником отклоняется.
- `kb-meeting-link-change`, `kb-meeting-links`, `kb-meeting-backlinks`, `kb-undo`: ручные связи и обратные ссылки доступны; чтение встреч выполняется вне блокировки заметок, чтобы не создавать инверсию блокировок.

Расчёт выполняется в utility task вне главного потока. Запросы отменяются при закрытии представления, смене области и начале записи; правки заметок/папок/списка встреч запускают обновление с задержкой 250 мс. Перед публикацией сравнивается снимок заметок, заново проверяются права, контрольная точка встреч и актуальность manifest. Изменение входов приводит к ошибке обновления, а не к частично устаревшему названию.

## Проверки и измеренное качество

В Rust проверяются: источники за прежней границей 100 встреч, страницы и возобновление индекса, scope и текущие права, повреждённые/длинные файлы, актуальность конспекта, версия при открытии, подмена якоря, отмена, отсутствие транзитивного слияния, semantic veto, обратные ссылки, идемпотентный replay и tombstone после идентичного восстановления. Нативные проверки выполняют сохранение/удаление/отмену ручной связи и переход из смешанной темы в точный транскрипт на одноразовой библиотеке.

Воспроизводимый реальный прогон: `scripts/eval_mixed_product.py`. Он создаёт одноразовую библиотеку, вызывает `note-save`, `semantic-config`, `semantic-refresh`, `kb-mixed-topics`, использует установленную локальную модель и настоящий сохранённый индекс. Личная библиотека и сеть не используются. Проверка метрик: `scripts/test_eval_mixed_product.py`.

Корпус `scripts/fixtures/knowledge-mixed-product-v1.json` был зафиксирован **до inference**, SHA256 `e833f6007a43c0f737d32653da9dd4c251e7d834d19ec1065a375a96c34c3784`. Темы calibration/holdout не пересекаются; пары размечены заранее. Отчёт: `scripts/fixtures/knowledge-mixed-product-v1-result.json`.

| Выборка | Документы | Верные/все предложения | Recall | Покрытие источников с ожидаемой парой |
| --- | ---: | ---: | ---: | ---: |
| Calibration, threshold 0.58 | 10 | 4/4 | 100% | 100% |
| Независимый holdout, тот же threshold | 20 | 7/7 | 87.5% | 87.5% |
| Лексический baseline на holdout | 20 | 0 предложений | 0% | 0% |

Holdout пропустил одну пару о выращивании томатов. Порог после этого не изменялся. Это небольшой синтетический набор, а не доказательство 100% точности на личных материалах и не проверка качества автоматически придуманных названий. Прежние «4 верных из 6» получены другим алгоритмом на другом корпусе; прямое числовое сравнение этих результатов некорректно. Нужны последующие добровольные пользовательские оценки, а не новый запрет на локальный просмотр предложений.
