# Встроенный смысловой поиск After

## Продуктовый маршрут

В настройках поиска доступна «Встроенная модель After». Кнопка «Подготовить и
включить» явно скачивает проверенные компоненты и Qwen3 Embedding 0.6B, проверяет
модель, сохраняет конфигурацию и запускает фоновый индекс. Отдельный сервер,
API-ключ и установка Ollama не нужны. Новый профиль по умолчанию использует этот
маршрут, но выключен до действия пользователя. Существующие настройки Ollama или
совместимого API сохраняются; их можно переключить вручную.

Реализация: `rust-core/src/managed_embeddings.rs`,
`rust-core/src/platform/macos/managed_embedding_transport.rs`, `rust-core/src/semantic.rs`,
`Sources/AfterApp/SemanticSearchSettings.swift`.

Поддерживается macOS на Apple Silicon. Выбранный arm64 slice `llama-server`
ссылается только на системные frameworks; отдельные dylib из архива не
загружаются. Выполнение ограничено CPU, двумя потоками, одним slot и контекстом
4096 токенов. Один процесс обслуживает весь пакет до восьми текстов, а не
запускается для каждого текста отдельно. UI, фоновый индекс и вопросы Джарвиса
используют один Rust-маршрут `embed(root, ...)`.

## Граница доверия

Защищаем от повреждённых/неверных компонентов, случайного чужого локального
сервера, передачи данных после отзыва конфигурации и неявного облачного fallback.
Произвольный вредоносный процесс того же пользователя с доступом ко всем его
файлам и памяти не входит в границу приложения. Защита macOS-аккаунта не
подменяется дополнительным протоколом внутри After.

Исполняемый файл и GGUF проверяются по закреплённому SHA-256. Разрешены обычные
файлы владельца с одним hardlink; symlink отвергается. Успешная проверка
кэшируется по inode/размеру/mtime/ctime; изменение файла заставляет пересчитать
hash. Манифест индекса содержит постоянную версию модели, размерность,
нормализацию и шаблоны, но не путь временного сокета.

Каждый процесс создаёт свой каталог `0700` в `/private/tmp`. Перед передачей
любого текста подключённый Unix socket проверяется через `LOCAL_PEERPID` и
`getpeereid` против живого дочернего процесса. До готовности отправляется только
публичная тестовая фраза. У пользовательского запроса нет redirect, proxy,
переподключения или перехода на случайный HTTP-порт. Клиент ограничивает размер
запроса, ответа и время; ошибки прекращают операцию.

## Установка и идентичность

Установка находится в `<library>/runtime/semantic`:

- `After Embeddings` — закреплённый runtime из Ollama v0.40.3;
- `qwen3-embedding-0.6b.gguf` — модель, 639 150 592 байта;
- лицензии runtime, включая upstream notices.

Публичные загрузки выполняет только явный `semantic-pull`: HTTPS без proxy и
ключей, ограничение размера, проверка SHA-256 до установки. Redirect разрешён
только для официальных GitHub/registry asset hosts и их R2 object storage.
Можно переиспользовать совпадающие по hash файлы ранее установленного runtime.
Обычные status/check/index/search никогда не скачивают модель.

| Компонент | SHA-256 |
| --- | --- |
| Runtime archive | `a2d1d906a2c8febd9cb18f5c183854d0a6db5dc522940d68b0c0ed048e8dfdea` |
| `After Embeddings` | `3efd976f34a2469901b62c838f8b47a47f2a31bec403b4a287567a40f38658d4` |
| GGUF | `06507c7b42688469c4e7298b0a1e16deff06caf291cf0a5b278c308249c3e439` |

Конфигурация: `provider=managed`, пустой endpoint, `model=qwen3-embedding:0.6b`,
1024 измерения, `modelRevision=qwen3-embedding-0.6b-06507c7b-llama-v0.40.3-cpu-v1`.
Проверка модели возвращает этот стабильный профиль. Конфигурация с другим
endpoint, revision, размерностью или облачным разрешением отвергается.

## Ресурсы и отмена

Managed inference использует общий межпроцессный file lock одной библиотеки.
В native-приложении проверка модели, индекс, интерактивный поиск и voice-plan
с локальным поиском также получают `localRuntimeLease`, общий с ASR и генерацией.
Перед запуском и передачей проверяются feature/config и запись.

Скачивание компонентов удерживает только отдельный install lock; оно не занимает
inference lease и не задерживает сохранение аудио или ASR. Настройки можно закрыть.
«Отменить включение» отзывает автоматическую активацию, но не прерывает текущий
блокирующий сетевой запрос: он завершается в фоне. Повтор допускается после его
завершения. Частичные файлы не считаются готовыми; публикация остаётся атомарной
с проверкой закреплённых хешей. Новые сохранённые настройки не перезаписываются
результатом ранее запущенной подготовки.

`RecordingCoordinator` удерживает отдельный recording lock с начала подготовки
записи. Модель отменяется, запись не ждёт её освобождения. После остановки или
ошибки запуска lock явно снимается; при смерти приложения его закрывает ОС.
Выключение semantic search или изменение профиля прерывает managed inference и
не позволяет опубликовать старый результат. При недоступной модели обычный
текстовый поиск продолжает работать с объяснением ограничения.

При штатной ошибке, таймауте или отмене дочерний процесс завершается и временная
папка удаляется. После `SIGKILL` приложения немедленная уборка дочернего процесса
не гарантируется: runtime настроен выгружать модель после двух секунд простоя.
Это ограничение не следует выдавать за полную crash-cleanup гарантию.

## Проверки и измерения

`scripts/check_managed_semantic.py` использует свежую временную библиотеку,
копии закреплённых файлов и синтетические заметки. На тестовом Mac под sandbox,
полностью запрещающей IP-сеть, прошли:

- явная подготовка, реальный вектор 1024D, индекс и межъязычный поиск;
- отказ до загрузки модели во время записи и поиск после снятия lock;
- выключение конфигурации во время загрузки — отмена без выдачи результата;
- завершение дочернего процесса и удаление его временной папки.

В debug-сборке: check 0,98 с, индекс трёх заметок 1,00 с, запрос 0,71–0,76 с.
Первичная SHA-проверка больших файлов заняла 21,58 с; последующие вызовы
используют проверенный metadata stamp. Это измерение одного Mac, не SLA.

Rust-регрессии проверяют владельца сокета, чужой процесс, отмену, malformed и
oversized ответы, ограниченный timeout, изменённые/подменённые assets, общий
lease, recording lock между процессами, stale manifest и отсутствие
автоматических загрузок. Публичные cached-vector API не запускают модель и не
читают источники вне переданного разрешённого набора; встречи включают только
актуальные transcript/summary fragments, не заголовки.

`scripts/eval_managed_semantic.py` прогнал реальный индекс FFI на замороженных
наборах по 30 заметок. Порог 0,43 был зафиксирован прежней калибровкой до запуска
holdout. В managed-маршруте holdout дал 78 релевантных из 81 показанного
результата, recall@3 65%, результат у 30 из 30 запросов. Полные метрики и hashes
корпусов: `scripts/fixtures/knowledge-semantic-managed-result.json`.

Порог 0,43 применяется только к подтверждаемым вручную подсказкам связей для
точной проверенной модели и пустого document prefix. Это маленькая
синтетическая проверка; она не обещает качество на личных библиотеках и не
используется как порог смешанных тем. Их отдельная оценка и правило описаны в
`knowledge-mixed-topics.md`.

Для повторения проверок передаются `--library` (собранная dylib), `--runtime`
(уже имеющийся pinned llama-server), `--model` (GGUF); ни один скрипт не скачивает
компоненты и не использует личную библиотеку. Проверка точного установочного
пакета и аппаратная запись с переключением устройств остаются отдельными
приёмочными действиями, а не результатом этих модельных тестов.
